## AI에게: 기록 규칙

이 파일을 읽은 AI는 `modules/media/` 작업이 끝날 때마다 아래 규칙대로 기록해 주세요.

**기록하는 것**
- 결과가 잘 나와서 담당자가 받아들인 프롬프트
- 처음엔 실패했지만 프롬프트를 고쳐서 해결한 경우 (실패한 프롬프트와 고친 프롬프트 모두)
- AI가 틀린 정보를 지어내거나(환각), 시키지 않은 파일을 고치는 등 실수를 막은 프롬프트
- 앱 안에서 쓰는 AI 프롬프트(시스템 프롬프트 등)를 새로 만들거나 고친 경우

**기록하지 않는 것**
- "안녕", "응", "맞아", "고마워", "ㅇㅋ", "다시 해 줘", "계속" 같은 짧은 말
- 오타 수정, 파일 위치 묻기처럼 결과가 남지 않는 단순 요청
- 이미 기록한 것과 거의 같은 프롬프트

**쓰는 방법**
- 프롬프트는 담당자가 쓴 **원문 그대로** 넣습니다. 다듬거나 요약하지 않습니다.
- API 키, 비밀번호, Supabase 주소, 개인정보는 `***`로 가립니다.
- 새 기록은 `## 기록` 맨 아래에 번호를 이어서(P-01, P-02 …) 추가합니다. 이전 기록은 고치거나 지우지 않습니다.
- 기록을 추가했다면 `## 요약`의 표도 한 줄 갱신합니다.
- 앱 안 AI 프롬프트를 고쳤다면 `## 앱 안 AI 프롬프트 버전`에도 한 줄 추가합니다.
- 기록했다면 작업 끝에 "프롬프트 기록에 P-00을 추가했습니다"라고 알려 줍니다.

**기록 형식** (이 형식만 사용)

- 문제 유형: 환각(없는 정보 지어냄) / 다른 파일 수정 / 기존 코드 삭제 / 형식 깨짐 / API 버전 오류 / 없음 등

### P-01 · 2026-10-24 · 메인 이미지 A/B 섹션 추가 (문제 시나리오, PM 작업)

문제 시나리오.md  넣었고 그거 기반대로 만들어줘
```

```

**해결 전략**: 시나리오의 '가설과 소재 연결'을 기준으로, 아마존 메인 이미지 규칙(흰 배경 실제 사진, AI 연출 금지) 안에서 바꿀 수 있는 변수(각도·펼친 상태·두께감)로 A/B 안을 만들고, 승자는 CTR(시장 대비 배수)로 고르되 CVR이 0.5%p 넘게 떨어지면 실패로 보는 판정을 두 비율 z-검정으로 계산. CAC는 적용 전후 4주 비교로만 표시
**결과**: media_ab.py(A/B 안, 규칙, 촬영 브리프 다운로드, AI 각도 레퍼런스 프롬프트, Manage Your Experiments 안내, 가상 결과·판정·CAC), data/media_ab_result_dummy_202610.json, media_page.py에서 호출
**다음에 쓸 팁**: 플랫폼 규칙(아마존 메인 이미지 등)이 있는 소재는 "규칙 안에서 바꿀 수 있는 변수만 A/B로" 요청하면 쓸 수 없는 안이 나오지 않는다

### P-02 · 2026-10-24 · A/B 단일 변수 선정 섹션 추가

- 분류: 기능 구현
- 문제 유형: 없음

**잘 쓴 프롬프트 (원문)**
```text
아니 나 미디어 담당자라서 지금 3번 탭 진행할거야. 2번 탭에서 받아올 가설을 [ 만약 메인 이미지를 펼친 패드의 냉감 원단 질감과 두께가 보이는 각도로 바꾸면, 저가 제품과의 품질 차이가 바로 보여서, 'kühlende matratzenauflage' 검색에서 클릭 점유율 ÷ 노출 점유율이 0.63배에서 0.8배 이상으로 오를 것이다.] 라고 고정할게. 

그럼 위 가설을 기반으로 A/B 테스트를 진행할 때 단일 변수 선정하는 것 까지만 먼저 해보자.
```

**처음 시도와 문제**
- 처음 프롬프트: "그런데 3번 탭에서 가설에 따른 단일 변수를 하나 뽑아서 A/B 테스트를 진행하는데 집중해야 하는데 지금 가설이 너무 모호한 것 같아. 어떻게 이 상황을 해결할 수 있을까? 어디가 문제야?"
- AI가 한 실수: 없음. 2번 탭 규칙 기반 문장(키워드 미일치로 기본 액션 "타깃 맞춤 프로모션 집중 노출", 무관한 독일 DB 근거, 기본 개선량 10%)이 원인임을 찾았지만, hypothesis 모듈은 담당이 아니라 수정하지 않음

**해결 전략**: 남의 모듈을 고치는 대신 3번 탭에서 쓸 가설 문장을 담당자가 직접 고정하고, 작업 범위를 "단일 변수 선정까지만"으로 좁힘
**결과**: media_variable.py 추가 (가설 If/Because/Then 분해 → 후보 변수 6개를 가설 연결·아마존 메인 이미지 규칙·Manage Your Experiments 가능 여부로 거름 → 독립 변수 "메인 이미지 촬영 구도" 1개, A/B 수준, 통제 변수, 종속 변수, 안전장치 표), media_page.py에서 media_ab_section()보다 먼저 호출, media.md 파일 표 갱신
**다음에 쓸 팁**: 앞 단계 결과물이 모호하면 내 모듈에서 쓸 입력값을 문장째 고정해 주고, 단계를 하나씩 끊어 요청하면 남의 모듈을 건드리지 않고 진행할 수 있다

### P-03 · 2026-10-24 · 프롬프트 A/B 삭제, '가설에서 변수 도출' 블록으로 재구성

- 분류: 디자인
- 문제 유형: 없음

**잘 쓴 프롬프트 (원문)**
```text
지금 구현된 화면에서 프롬프트 A,B는 일단 삭제하고, '가설에서 변수 도출' 이라는 항목으로 블록 만들고, 가설 2번 탭에서 가져오는 흐름으로 화면 구상해줘.
```

**처음 시도와 문제**: 없음

**해결 전략**: ② 탭 저장값(store "hypothesis")을 먼저 보여 주고 ①가져오기 → ②나누기 → ③후보 거르기 → ④단일 변수 선정 순서의 한 블록으로 묶음. 저장값이 없으면 기준 가설로 대신하고, 기준 가설과 다르면 아래 표가 맞지 않는다고 경고
**결과**: media_page.py (프롬프트 A/B 칸 삭제, 페이지 설명 변경), media_variable.py (블록 재구성, media_variable_hypothesis() 추가), media.md 갱신
**다음에 쓸 팁**: 다른 탭 값을 가져오게 할 때 "없을 때 / 예상과 다를 때" 화면을 같이 정해 두면 시연 중 빈 화면이나 엉뚱한 표가 나오지 않는다

### P-04 · 2026-10-24 · 가설 콜아웃을 If / Because / Then 구조로 표시

- 분류: 디자인
- 문제 유형: 없음

**잘 쓴 프롬프트 (원문)**
```text
가설을 콜아웃으로 보일때, "만약 [타깃/지점]에 [구체적인 액션]을 적용한다면(If),
[이유/고객 심리] 때문에(Because),
[측정 가능한 지표/KPI]가 [얼마나] 개선될 것이다(Then)."
이 구조가 사용자에게 시각적으로 조금 더 잘 보일 수 있도록 해줘.
```

**처음 시도와 문제**: 없음

**해결 전략**: 가설 문장을 쉼표·"때문에" 기준으로 세 덩어리로 나눠 If/Because/Then 태그 + 빈칸 이름(타깃·액션 / 이유·고객 심리 / KPI·얼마나)을 붙인 줄로 표시, Then 줄은 진하게 강조. 나눌 수 없는 문장은 한 덩어리로 표시하고, 사용자 입력은 HTML 이스케이프. 색은 공통 CSS 변수만 사용
**결과**: media_variable.py (media_variable_split(), media_variable_callout() 추가, 기존 '가설 나누기' 표는 콜아웃과 중복이라 삭제하고 단계 번호 ①~③으로 정리), media_style.css (media-hypo-* class)
**다음에 쓸 팁**: 문장 틀을 그대로 붙여 주면 AI가 틀의 빈칸 이름까지 화면 라벨로 재사용해서, 화면 용어가 기획 문서와 맞춰진다
