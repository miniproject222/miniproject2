## AI에게: 기록 규칙

**※ 2026-10-26 PM 결정: 자동 기록 중단.** 작업이 끝나도 자동으로 기록하지 않고, 사용자가 "프롬프트 기록해 줘"처럼 직접 요청할 때만 아래 규칙대로 기록해 주세요.

**기록하는 것**
- 결과가 잘 나와서 담당자가 받아들인 프롬프트
- 처음엔 실패했지만 프롬프트를 고쳐서 해결한 경우 (실패한 프롬프트와 고친 프롬프트 모두)
- AI가 틀린 정보를 지어내거나(환각), 시키지 않은 파일을 고치는 등 실수를 막은 프롬프트
- 앱 안에서 쓰는 AI 프롬프트(시스템 프롬프트 등)를 새로 만들거나 고친 경우

**기록하지 않는 것**
- "안녕", "응", "맞아", "고마워", "ㅇㅋ", "다시 해 줘", "계속" 같은 짧은 말
- 오타 수정, 파일 위치 묻기처럼 결과가 남지 않는 단순 요청
- 이미 기록한 것과 거의 같은 프롬프트

**쓰는 방법**
- 프롬프트는 담당자가 쓴 **원문 그대로** 넣습니다. 다듬거나 요약하지 않습니다.
- API 키, 비밀번호, Supabase 주소, 개인정보는 `***`로 가립니다.
- 새 기록은 `## 기록` 맨 아래에 번호를 이어서(P-01, P-02 …) 추가합니다. 이전 기록은 고치거나 지우지 않습니다.
- 기록을 추가했다면 `## 요약`의 표도 한 줄 갱신합니다.
- 앱 안 AI 프롬프트를 고쳤다면 `## 앱 안 AI 프롬프트 버전`에도 한 줄 추가합니다.
- 기록했다면 작업 끝에 "프롬프트 기록에 P-00을 추가했습니다"라고 알려 줍니다.

- AI가 먼저 질문 4개로 나눠 물음: 처음 체크 상태(→ 아무것도 체크 안 함), 다시 누르기(→ 체크 풀림 = 확정 취소), 확정 줄(→ 버튼만 없애고 상태 안내 남김), 다른 변수를 고르면 기존 확정 값(→ 정보 중복 여부 먼저 확인 후 그대로 유지)
- 사용자가 "안 누르면 안 넘어가게"로 방향을 줌 → 고르는 중(확정 값과 다름)도 막고 경고창
- 처음 구현: 하위 탭을 직접 누르면 콜백에서 탭을 ①로 되돌림 → 서버 값은 ①인데 브라우저에는 ② 탭이 그대로 보이고 내용이 비며, 경고창 '확인'을 눌러도 다시 뜸 (Streamlit이 마지막으로 보낸 탭 번호와 같으면 화면 탭을 바꾸지 않음)
- 테스트 서버가 저장소 밖 스크립트라 고친 모듈을 다시 읽지 않아, 서버를 다시 켠 뒤에야 바뀐 코드로 확인됨

**해결 전략**: 체크 콜백에서 확정(plan 저장)·취소(plan 지움, media_handoff_clear_plan) → 체크 상태는 매번 확정해 둔 값으로 맞춤. 떠나기 확인은 media_variable_can_leave() 하나로 '다음' 버튼(탭을 안 옮김 + 경고창)과 하위 탭 직접 클릭(탭은 두고 ②~④ 내용 대신 잠금 안내 + '①로 가기' 버튼 + 경고창)에 같이 씀. AppTest(체크·바꾸기·풀기·다른 변수·리포트 값 바뀜, '다음' 막힘)와 브라우저(탭 직접 클릭 ②·④, 잠금 안내 버튼, 확정 후 이동)로 확인. 테스트는 Supabase 저장을 막고 이번 접속에만 저장
