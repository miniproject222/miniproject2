# 3. 매체 제작 (`media`)

- 매체 제작: 하위 탭 4개 가설에서 변수 도출 → A/B 소재 준비(아래쪽에 프롬프트 만들기·AI 다듬기) → 사진·영상 초안 제작 → 외주 정리 (2026-10-25 PM 결정: 프롬프트 만들기 탭을 A/B 소재 준비에 합침) (둥근 알약형 탭) (각 단계 아래 이전/다음 버튼으로 이동)
- 끝은 외주업체에 넘길 레퍼런스 파일(프롬프트, 사진·영상 초안, 고정 요소) 준비까지입니다. A/B 결과 판정, UTM, 매체 외 솔루션 제안은 지금 흐름에서 빠졌습니다 (판정 코드는 `media_stage2/media_stage2_judge.py`에 보관)

## 3단계 나눠 개발 (동시 개발 후 1단계 기준으로 합침)

| 단계 | 하위 탭 | 브랜치 | 담당 폴더·파일 | 이름 접두어 |
|---|---|---|---|---|
| 1단계 | 단일 변수 추출 ~ A/B 소재 선정 (① 가설에서 변수 도출, '이 변수로 확정') | `min` | `modules/media/` 바로 아래 파일 전부 (공용 파일 포함) | `media_` / `media-` |
| 2단계 | ② A/B 소재 준비: ①에서 확정한 A·B 카드 → 기본 프롬프트 → 빈칸 → A, B 채우기 → 리포트 값으로 AI 다듬기 + 확인 | `JH`(PM, 원래 `JY`) | `media_stage2/`만 | `media_s2_` / `media-s2-` |
| 3단계 | ④ 사진·영상 초안 제작(프롬프트로 사진 초안, 스토리보드 → 영상 초안) → ⑤ 외주 정리(브리프 + zip) | `DH` | `media_stage3/`만 | `media_s3_` / `media-s3-` |

- 공용 파일(`media_page.py`, `media_handoff.py`, `media_style.css`, `media.md`, `media_prompt.md`, `CLAUDE.md`)은 1단계 담당자만 고칩니다.
- 연결 지점: `media_page.py`가 하위 탭에서 `media_stage2_render()`(②), `media_stage3_render()`(③), `media_stage3_export_render()`(④)만 부릅니다.
- 2·3단계 하위 탭 이름은 각 단계 파일의 `MEDIA_S2_TAB_LABEL`, `MEDIA_S3_TAB_LABEL`, `MEDIA_S3_EXPORT_TAB_LABEL`에서 정하고 `media_page.py`가 가져다 씁니다. 단계 담당자가 직접 바꿉니다.
- 단계 사이 데이터: `media_handoff.py` (1→2 `media_handoff_set_plan()` / `media_handoff_plan()`, 2→3 `media_handoff_set_prompt()` / `media_handoff_prompt()`, ④→⑤ `media_handoff_set_assets()` / `media_handoff_assets()`).
  - 값은 **Supabase 공용 저장소**(`store("media")`의 `handoff` 칸: `plan`, `prompt`, `assets`)에 저장됩니다. 프로젝트 파일은 바뀌지 않아 커밋·충돌이 생기지 않고, 다른 컴퓨터에서도 바로 이어집니다. (읽을 때 3초마다 Supabase에서 새로 읽음)
  - **각 단계의 넘기기 버튼을 눌렀을 때만** 저장됩니다. 화면을 열기만 해서는 저장되지 않습니다. 앞 단계가 아직 안 넘겼으면 예시 값(`sample: True`)이 와서 각자 먼저 개발할 수 있습니다.
    - ①: 따로 확정 버튼 없이 **B안 옵션 체크 = 확정**, 체크한 옵션을 다시 눌러 풀면 **확정 취소**(`media_handoff_clear_plan()`으로 넘긴 plan을 지움). 처음에는 아무것도 체크되지 않습니다. 선정 표 아래 줄(`media_variable_confirm_step()`)은 상태 안내만 보여 주고, 확정한 뒤 리포트 값 등이 바뀌면 체크가 비워지며 '다시 확정 필요'가 보입니다(다시 체크하면 새 값으로 확정).
      확정 전(또는 고른 변수·옵션이 확정한 값과 다르면) ①을 떠날 수 없습니다: '다음' 버튼은 탭을 옮기지 않고 가운데 경고창(`media_variable_can_leave()`, 이유는 '확정한 변수 없음 / 확정한 값과 다름 / 이미지로 해결할 수 없는 변수'), 하위 탭 ②~④를 직접 누르면 경고창과 함께 그 탭 내용 대신 잠금 안내(`media_variable_locked_step()`, '①로 가기' 버튼)가 보입니다. (`media_page.py`의 `MEDIA_STEP_ON_NEXT`, `_media_step_changed()`)
      확정할 때 고른 B안의 영어 레퍼런스 프롬프트(후보 묶음의 `ref_prompt`, AI가 만들지 않았으면 빈 문자열)도 `b_ref`로 같이 넘기고, 2단계는 여기서 빈칸 B를 잘라 씁니다.
      하위 탭 ② A/B 소재 준비부터는 모두 이 확정 값을 씁니다. ①에서 고르기만 하고 확정하지 않았으면 ②는 이전 확정 값을 보여 주며
      '확정 안 됨' 안내와 '① 으로 가서 확정하기' 버튼을 띄우고, 한 번도 확정하지 않았으면 A/B 대신 빈 카드와 같은 버튼만 보여 줍니다.
      `MEDIA_HANDOFF_PLAN` 기본값에 1번 리포트 값(`sqp.query`, `sqp.listing.main_image` → `a`, `sqp.ratio` → `kpi_now`, `sqp.kpi_goal`)을 덮어쓴 값입니다. KPI 숫자(`kpi_now`, `kpi_goal`)는 가설이 리포트 검색어 클릭 분석의 KPI를 말할 때만 넣고, 아니면 `kpi`는 가설의 지표 이름, 숫자는 `None`입니다.
      불러온 가설에 메인 이미지 변수가 없으면(예: 배송비 → 결제 완료율) 2·3단계가 이어받을 수 없어 확정 버튼이 꺼집니다 (기준 가설은 없앰).
    - ③: '④로 넘기기' 버튼 (`media_s2_handoff_step()`, 확인을 통과해야 눌림)
    - ④: '⑤로 넘기기' 버튼 (`media_s3_handoff_step()`, 스토리보드를 확정해야 눌림). 사진·영상 파일 자체는 크기 때문에 Supabase에 넣지 않고 같은 브라우저 접속 안에만 둡니다.
  - Supabase는 팀 전체가 같은 값을 보므로, 누군가 다시 넘기면 모두의 다음 단계 화면이 그 값으로 바뀝니다.
  - Supabase에 연결할 수 없으면(`.streamlit/secrets.toml` 없음) 같은 브라우저 접속 안에서만 이어집니다.
  - 2→3 모양(`MEDIA_HANDOFF_PROMPT_SAMPLE`): `variable` 단일 변수, `base` 기본 프롬프트(빈칸 `{slot}`), `slot_a`, `slot_b` 빈칸 문구, `fixed` 고정 요소, `prompt_a`, `prompt_b`, `changes`, `avoid`, `include`
- 단계 폴더의 CSS(`media_stage2_style.css`, `media_stage3_style.css`)는 공통 로더가 읽지 않아 `media_page.py`의 `media_load_stage_css()`가 넣습니다.
- 각 단계의 기능 명세·AI 안내·프롬프트 기록은 단계 폴더의 `media_stageN.md`, `CLAUDE.md`, `media_stageN_prompt.md`에 있습니다.

| `media_variable.py` | 하위 탭 ① 가설에서 변수 도출(`media_variable_step()`): 2026-10-26부터 가설 불러오기 버튼을 없애고 자동으로 불러옴: 이번 접속에서 아직 안 불렀거나 2번 탭에서 다른 가설을 저장했으면(`media_variable_is_stale()`) 화면을 그릴 때 바로 `media_variable_load()`를 부름 (3번 탭 내용은 다른 탭을 보고 있을 때도 같이 그려지므로 3번 탭을 직접 눌러 들어와도 이미 불러온 화면. 자동으로 불러올 때는 토스트 없음). 페이지 제목 줄 오른쪽 끝에는 다른 사람이 방금 저장한 가설을 다시 읽는 '↻ 다시 불러오기' 버튼만 둠. 2번 탭에 저장된 가설이 없으면 점선 빈 카드 대신 요약 칩과 같은 모양·자리의 안내 칩 ':gray-badge[가설 없음] 2번 가설 탭에서 가설을 고르고 다음으로를 누르면 여기로 불러와요'. 불러온 뒤에는 ②~④의 목표 KPI 칩과 같은 모양의 요약 칩(`media_variable_summary_chip()`, key `media-hypo-summary`)을 화면 1440px 이상에서 하위 탭 바와 같은 줄 오른쪽 끝에 띄움(더 좁으면 탭 바 아래 줄 오른쪽, 독립 변수 이름이 길면 탭 바를 덮지 않고 두 줄로 꺾음). KPI '클릭 점유율 ÷ 노출 점유율'은 화면에서만 '노출 대비 클릭률'로 보여 주고 가설 원문은 그대로 둠(2번 탭이 어느 쪽으로 저장해도 같은 가설로 봄)(넓은 화면만, 좁은 화면은 전체 폭). 불러올 때는 스피너 동안 2번 탭 가설을 Supabase에서 다시 읽고(`store_get("hypothesis", fresh=True)`, `media_variable_load()`) 그 가설로 후보 묶음을 만든 뒤(`media_variable_ai.py`) 아래 내용이 나타남 ('다시 불러오기'를 눌렀을 때만 토스트). 불러온 가설과 후보 묶음은 session_state(`media-variable-hypo`, `media-variable-gen`)에 두어, 2번 탭에서 다른 가설을 저장하면 자동으로 다시 불러오고, 같은 가설이면 AI를 다시 부르지 않음. 2번 탭 저장값은 새 모양(`selected`의 sentence·if·because·then·problem)을 먼저 읽고 없으면 예전 평평한 키(text, if_text …)를 읽음(`media_variable_saved()`). 2026-10-26 가설 콜아웃은 없앰: 위에는 요약 칩 한 줄에 '독립 변수 · 🎯 목표 KPI'를 보여 줌(글자 폭만큼, 나타나는 애니메이션 상자 밖에서 그림)(목표 KPI는 리포트 숫자가 있으면 `media_variable_kpi_text()`, 없으면 가설의 Then을 '지표 A → B (N%↑)'로 줄여 보여 줌, `media_variable_goal_text()`·`media_variable_short_then()`). 불러온 가설의 If / Because / Then 원문은 요약 칩 ⓘ(`media_variable_hypo_tip()`). 불러온 가설이 2번 탭에 지금 저장된 가설과 다르면(2번 탭에서 다른 가설을 고른 뒤 다시 불러오지 않음) 자동으로 다시 불러옴(`media_variable_is_stale()`, 이번 접속에 기억해 둔 값으로만 비교해 다른 사람이 저장한 값은 다시 불러와야 반영) (`media_variable_hypothesis_step()`, AI 대신 규칙으로 만든 후보면 '규칙으로 만든 후보' 안내 + ⓘ에 이유), 아래 왼쪽 '후보 변수 선택' 블럭에서 A/B로 실험할 변수를 고르고, 오른쪽 '선정한 단일 변수'에서 그 변수를 A/B로 나눔 (`media_variable_derive_step()`). 블럭 하나 = 변수 하나 (예: 메인 이미지 촬영 구도 / 제목 앞 문구 / 가격·쿠폰). 후보는 불러온 가설로 만든 묶음의 `variables`에 있고(변수마다 B안 목록 `b_options`, 읽는 곳은 `media_variable_candidate_set()`; 2026-10-26부터 묶음을 만들 때 코드가 한 번 더 거름(`media_variable_clean_set()`): ① 가설에 맞는 변수만 — 가설 If의 종류(메인 이미지·제목·불릿·A+·가격·광고·입찰, `media_variable_kind()`)와 다른 변수는 AI가 맞다고 해도 '가설의 If와 다름'으로 바꾸고 B안을 버림 (예: 고온일 키워드 입찰 가설에서 메인 이미지 변수가 진행 가능으로 나오지 않게, 종류 'ad' 추가), ② 단일 변수 — B안이 통제 변수(조명·보정, 흰 배경, 제품·색상)나 다른 변수(제목·가격·광고 등)까지 바꾸면 B로 쓰지 않고 ⓘ의 'B로 못 쓰는 안'으로 돌림(`media_variable_single_break()`), ③ 서로 다른 안만 — 앞의 B안과 문장이 비슷하면(difflib 0.7 이상) 빼고 B로 쓸 수 있는 안은 최소 2개·최대 3개(`MEDIA_VARIABLE_B_MIN`·`MEDIA_VARIABLE_B_MAX`): AI에게 정확히 3개를 요청하고, 코드 확인 뒤 진행할 메인 이미지 변수의 B안이 2개보다 적으면 빠진 이유를 붙여 AI마다 2번까지 다시 요청(Gemini가 끝내 모자라면 OpenAI도 시도, `media_variable_generate()`·`media_variable_b_shortage()`). 그래도 모자라면 지어내지 않고 있는 만큼 보여 주며 B안 블럭 아래에 '옵션이 N개만 나왔어요' 안내, 이때는 같은 가설이라도 '다시 불러오기'에서 새로 만듦. ④ 간결하게 — 요약 칩·변수 블럭·A·B 카드에 보이는 칸은 `MEDIA_VARIABLE_TEXT_MAX`(변수 이름 16자, B안 이름 12자, B안 문장 60자) 안으로: 변수 이름은 괄호 설명을 빼고 그래도 길면 종류 이름(예: '메인 이미지', 다른 변수와 겹치면 잘라서 …), B안 이름은 잘라서 …, B안 문장이 길면 B로 쓰지 않음(`media_variable_short_name()`, `media_variable_cut()`). AI 지시문에도 '화면에 보이는 칸은 무조건 짧게, 핵심만'과 변수 이름 12자·B안 이름 10자·B안 문장 40자 기준을 넣음.
