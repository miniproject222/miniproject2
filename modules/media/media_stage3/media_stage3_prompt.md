쌓인 기록은 프롬프트 엔지니어링 기록(보고서)의 `media` 파트에 합칩니다. (1단계 기록: `modules/media/media_prompt.md`)

- 브랜치: `DH`

## AI에게: 기록 규칙

이 파일을 읽은 AI는 `modules/media/media_stage3/` 작업이 끝날 때마다 아래 규칙대로 기록해 주세요.

**기록하는 것**
- 결과가 잘 나와서 담당자가 받아들인 프롬프트
- 처음엔 실패했지만 프롬프트를 고쳐서 해결한 경우 (실패한 프롬프트와 고친 프롬프트 모두)
- AI가 틀린 정보를 지어내거나(환각), 시키지 않은 파일을 고치는 등 실수를 막은 프롬프트
- 앱 안에서 쓰는 AI 프롬프트(시스템 프롬프트 등)를 새로 만들거나 고친 경우

**기록하지 않는 것**
- "안녕", "응", "맞아", "고마워", "ㅇㅋ", "다시 해 줘", "계속" 같은 짧은 말
- 오타 수정, 파일 위치 묻기처럼 결과가 남지 않는 단순 요청
- 이미 기록한 것과 거의 같은 프롬프트

**쓰는 방법**
- 프롬프트는 담당자가 쓴 **원문 그대로** 넣습니다. 다듬거나 요약하지 않습니다.
- API 키, 비밀번호, Supabase 주소, 개인정보는 `***`로 가립니다.
- 새 기록은 `## 기록` 맨 아래에 번호를 이어서(P-01, P-02 …) 추가합니다. 이전 기록은 고치거나 지우지 않습니다.
- 기록을 추가했다면 `## 요약`의 표도 한 줄 갱신합니다.
- 앱 안 AI 프롬프트를 고쳤다면 `## 앱 안 AI 프롬프트 버전`에도 한 줄 추가합니다.
- 기록했다면 작업 끝에 "프롬프트 기록에 P-00을 추가했습니다"라고 알려 줍니다.

**기록 형식** (이 형식만 사용)

````
### P-00 · YYYY-MM-DD · 작업 제목

- 분류: 기능 구현 / 버그 수정 / 디자인 / 데이터 / 앱 안 AI 프롬프트 / 기타 중 하나
- 문제 유형: 환각(없는 정보 지어냄) / 다른 파일 수정 / 기존 코드 삭제 / 형식 깨짐 / API 버전 오류 / 없음 등

**잘 쓴 프롬프트 (원문)**
```text
담당자가 쓴 프롬프트 그대로
```

**처음 시도와 문제** (처음부터 잘 됐으면 "없음")
- 처음 프롬프트: "..."
- AI가 한 실수: ...

**해결 전략**: 프롬프트에서 무엇을 바꿨더니 해결됐는지 한두 줄
**결과**: 무엇이 만들어졌는지, 바뀐 파일
**다음에 쓸 팁**: 다른 작업에도 쓸 수 있는 요령 한 줄
````

## 기록

### P-01 · 2026-10-24 · 3단계를 '프롬프트 다듬기 → 매체 제작 → 외주 준비'로 다시 세팅

- 분류: 기능 구현
- 문제 유형: 없음 (명세 충돌을 먼저 짚고 진행)

**잘 쓴 프롬프트 (원문)**
```text
1단계. 단일 변수 추출 → A,B 테스트 소재 선정 (설계 담당)
2번 탭에서 고른 가설 1개에서 단일 변수를 하나 뽑아요. 예: 사진 각도
그 변수를 실험할 수 있는 A,B 테스트 소재를 정해요. 예: A는 접힌 패드, B는 모서리를 든 패드

여기까지 민이(1단계)

2단계. 프롬프트 다듬기 (설계 담당)
2-1. 기본 프롬프트 1개 쓰기
A와 B에 똑같이 들어갈 부분을 먼저 써요.
예: 흰 배경, 글자 없음, 냉감패드 90×200cm, 부드러운 조명

2-2. 단일 변수 칸 비워 두기
기본 프롬프트 안에 단일 변수 자리만 빈칸으로 남겨요.
예: "패드를 [ ] 상태로 찍은 사진"

2-3. 빈칸 채워서 A, B 만들기
A 빈칸: "접힌"
B 빈칸: "펼쳐서 모서리를 살짝 든"
그러면 프롬프트 두 개는 이 단어만 다르고 나머지는 똑같아요.

여기까지 준영 (2단계)

2-4. AI로 다듬기 + 확인
AI한테 표현을 더 좋게 다듬어 달라고 해요.
다듬은 뒤 A와 B를 나란히 놓고 비교해요.
빈칸 말고 다른 곳까지 달라졌으면 되돌려요.
넘길 것: 다듬은 프롬프트 A와 B, 그리고 고정한 요소 목록

3단계. 프롬프트를 통해 매체 (사진 동영상 초안) 제작
및 파일로 정리

여기까지 도훈 (3단계)

마지막
외주 레퍼런스 넘겨주기

자료를 취합 영상 사진 프롬프트 레퍼런스 등
그리고 취합한 내용을 외주업체를 위해 파일로 정리해서 보낼 준비 까지 하고 끝

(누구?) 마지막: 외주 레퍼런스 취합 → 외주용 파일 준비    이거까지 내가 DH가
이거대로 세팅해줘
```

**처음 시도와 문제**
- 처음 프롬프트: "2단계가 아직 개발 중이라 프롬프트를 다듬는 기능을 위해 뭐 부터 시작할지 알려줘."
- AI가 한 실수: 없음. 다만 기존 명세(2단계 판정 결과 → 솔루션 제안)와 맡은 일(판정 전 프롬프트·매체 제작)의 순서가 맞지 않아, 코드를 고치기 전에 충돌을 먼저 알림

**해결 전략**: 단계별 담당자와 하는 일을 한 번에 붙여 주고 "이거대로 세팅"이라고 해서 기준을 하나로 고정함
**결과**: `media_stage3.py`(예시 입력, 빈칸 확인 `media_s3_check()`, A/B 나란히 비교·되돌리기, 매체 올리기, 외주 zip `media_s3_package()`), `media_stage3.md`, `CLAUDE.md`, 이 파일의 깨진 기록 규칙 복구
**다음에 쓸 팁**: 다른 사람이 넘겨줄 값이 아직 없으면, 받을 값의 모양을 먼저 예시 상수로 정해 두고 그 함수 하나만 나중에 바꾸게 만든다

### P-02 · 2026-10-24 · 세 명이 새 흐름으로 일할 수 있게 media 구조·연결·문서 세팅

- 분류: 기타 (작업 환경 세팅)
- 문제 유형: 다른 파일 수정 (요청 범위를 넘어 기능까지 만듦)

**잘 쓴 프롬프트 (원문)**
```text
말고 내 일 하지 말고 세명이 일 할 수 있게 세팅만해놔
```

**처음 시도와 문제**
- 처음 프롬프트: "그걸 다 해줘 내가 pm 이야 한번에 하자"
- AI가 한 실수: '다 해줘'를 2단계 화면 기능 구현(프롬프트 입력·확인·넘기기)까지로 받아들여 JY 담당 기능을 직접 만들기 시작함

**해결 전략**: "세팅만"이라고 범위를 다시 정해, 각 단계가 일을 시작할 수 있는 구조(연결 함수, 탭 이름, 빈 뼈대, 문서, 자물쇠)만 남기고 기능은 담당자에게 남김
**결과**: `media_handoff.py`에 2→3 프롬프트 재료 함수(`media_handoff_set_prompt()`/`media_handoff_prompt()`), 2단계 빈 뼈대(탭 '프롬프트 만들기'), 이전 판정 코드 `media_stage2_judge.py`로 보관, 3단계 입력 연결, media·README·RULES·CLAUDE.md 흐름 수정, `.gitignore`에 자물쇠 파일 추가
**다음에 쓸 팁**: 여러 사람이 나눠 할 일을 AI에게 맡길 때는 "구조만"인지 "기능까지"인지 처음부터 말한다

### P-03 · 2026-10-24 · 다른 컴퓨터에서 작업해도 단계 사이 값이 이어지게

- 분류: 기능 구현
- 문제 유형: 없음

**잘 쓴 프롬프트 (원문)**
```text
그리고 다른 컴퓨터에서 단계 1이든 2이든 상관없이 작업 할때 작업물이 서로 연결될수있게 세팅해놔
```

**처음 시도와 문제**: 없음
**해결 전략**: 단계 사이 값이 브라우저 한 접속(session_state)에만 남는 문제를 짚고, 팀 공용 store(Supabase)에 `media`의 `handoff` 칸으로 저장하게 바꿈. 가짜 DB로 세 컴퓨터(1·2·3단계)를 따로 실행해 값이 이어지는지 확인
**결과**: `common/common_store.py`에 `store_get(key, fresh=True)`, `media_handoff.py`가 store로 저장·읽기(`media_handoff_set_plan()` 추가), media·README·RULES 문서 갱신
**다음에 쓸 팁**: "다른 컴퓨터에서도"라는 조건을 붙이면 저장 위치(세션인지 DB인지)부터 확인하게 된다

### P-04 · 2026-10-24 · Supabase 없이 파일 푸시·풀로 단계 사이 값 연결

- 분류: 기능 구현
- 문제 유형: 없음

**잘 쓴 프롬프트 (원문)**
```text
그냥 각자 올리면 자동으로 연결되게
```

**처음 시도와 문제**
- 처음 프롬프트: "supabase 하기 귀찮은데"
- AI가 한 실수: 없음. P-03의 Supabase 방식은 프로젝트·표·키 준비가 필요해 바로 쓸 수 없었음

**해결 전략**: 이미 쓰는 GitHub를 전달 통로로 삼아, 단계마다 자기 폴더의 JSON 파일 하나에 저장하고 읽을 때마다 새로 읽게 함 (P-03의 `store_get(fresh=True)` 변경은 되돌림)
**결과**: `media_handoff.py`가 `modules/media/data/media_handoff_plan.json`, `media_stage2/data/media_stage2_prompt.json`을 읽고 씀. 따로 실행한 세 번의 화면(1→2→3단계)에서 값이 이어지는 것 확인
**다음에 쓸 팁**: 함수 이름(set_prompt/prompt)을 그대로 두고 저장 위치만 바꾸면, 각 단계 코드를 안 고치고 방식을 바꿀 수 있다
