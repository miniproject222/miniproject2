## AI에게: 기록 규칙

이 파일을 읽은 AI는 `modules/media/media_stage3/` 작업이 끝날 때마다 아래 규칙대로 기록해 주세요.

**기록하는 것**
- 결과가 잘 나와서 담당자가 받아들인 프롬프트
- 처음엔 실패했지만 프롬프트를 고쳐서 해결한 경우 (실패한 프롬프트와 고친 프롬프트 모두)
- AI가 틀린 정보를 지어내거나(환각), 시키지 않은 파일을 고치는 등 실수를 막은 프롬프트
- 앱 안에서 쓰는 AI 프롬프트(시스템 프롬프트 등)를 새로 만들거나 고친 경우

**기록하지 않는 것**
- "안녕", "응", "맞아", "고마워", "ㅇㅋ", "다시 해 줘", "계속" 같은 짧은 말
- 오타 수정, 파일 위치 묻기처럼 결과가 남지 않는 단순 요청
- 이미 기록한 것과 거의 같은 프롬프트

**쓰는 방법**
- 프롬프트는 담당자가 쓴 **원문 그대로** 넣습니다. 다듬거나 요약하지 않습니다.
- API 키, 비밀번호, Supabase 주소, 개인정보는 `***`로 가립니다.
- 새 기록은 `## 기록` 맨 아래에 번호를 이어서(P-01, P-02 …) 추가합니다. 이전 기록은 고치거나 지우지 않습니다.
- 기록을 추가했다면 `## 요약`의 표도 한 줄 갱신합니다.
- 앱 안 AI 프롬프트를 고쳤다면 `## 앱 안 AI 프롬프트 버전`에도 한 줄 추가합니다.
- 기록했다면 작업 끝에 "프롬프트 기록에 P-00을 추가했습니다"라고 알려 줍니다.

**기록 형식** (이 형식만 사용)

````

- 분류: 기능 구현 / 버그 수정 / 디자인 / 데이터 / 앱 안 AI 프롬프트 / 기타 중 하나
- 문제 유형: 환각(없는 정보 지어냄) / 다른 파일 수정 / 기존 코드 삭제 / 형식 깨짐 / API 버전 오류 / 없음 등
````

### P-01 · 2026-10-24 · 3단계를 '프롬프트 다듬기 → 매체 제작 → 외주 준비'로 다시 세팅

- 분류: 기능 구현
- 문제 유형: 없음 (명세 충돌을 먼저 짚고 진행)

**잘 쓴 프롬프트 (원문)**
```text
1단계. 단일 변수 추출 → A,B 테스트 소재 선정 (설계 담당)
2번 탭에서 고른 가설 1개에서 단일 변수를 하나 뽑아요. 예: 사진 각도
그 변수를 실험할 수 있는 A,B 테스트 소재를 정해요. 예: A는 접힌 패드, B는 모서리를 든 패드

여기까지 민이(1단계)

2단계. 프롬프트 다듬기 (설계 담당)
2-1. 기본 프롬프트 1개 쓰기
A와 B에 똑같이 들어갈 부분을 먼저 써요.
예: 흰 배경, 글자 없음, 냉감패드 90×200cm, 부드러운 조명

2-2. 단일 변수 칸 비워 두기
기본 프롬프트 안에 단일 변수 자리만 빈칸으로 남겨요.
예: "패드를 [ ] 상태로 찍은 사진"

2-3. 빈칸 채워서 A, B 만들기
A 빈칸: "접힌"
B 빈칸: "펼쳐서 모서리를 살짝 든"
그러면 프롬프트 두 개는 이 단어만 다르고 나머지는 똑같아요.

여기까지 준영 (2단계)

2-4. AI로 다듬기 + 확인
AI한테 표현을 더 좋게 다듬어 달라고 해요.
다듬은 뒤 A와 B를 나란히 놓고 비교해요.
빈칸 말고 다른 곳까지 달라졌으면 되돌려요.
넘길 것: 다듬은 프롬프트 A와 B, 그리고 고정한 요소 목록

3단계. 프롬프트를 통해 매체 (사진 동영상 초안) 제작
및 파일로 정리

여기까지 도훈 (3단계)

마지막
외주 레퍼런스 넘겨주기

자료를 취합 영상 사진 프롬프트 레퍼런스 등
그리고 취합한 내용을 외주업체를 위해 파일로 정리해서 보낼 준비 까지 하고 끝

(누구?) 마지막: 외주 레퍼런스 취합 → 외주용 파일 준비    이거까지 내가 DH가
이거대로 세팅해줘
```

**처음 시도와 문제**
- 처음 프롬프트: "2단계가 아직 개발 중이라 프롬프트를 다듬는 기능을 위해 뭐 부터 시작할지 알려줘."

**해결 전략**: 단계별 담당자와 하는 일을 한 번에 붙여 주고 "이거대로 세팅"이라고 해서 기준을 하나로 고정함
