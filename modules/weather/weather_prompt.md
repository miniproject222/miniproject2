## AI에게: 기록 규칙

이 파일을 읽은 AI는 `modules/weather/` 작업이 끝날 때마다 아래 규칙대로 기록해 주세요.

**기록하는 것**
- 결과가 잘 나와서 담당자가 받아들인 프롬프트
- 처음엔 실패했지만 프롬프트를 고쳐서 해결한 경우 (실패한 프롬프트와 고친 프롬프트 모두)
- AI가 틀린 정보를 지어내거나(환각), 시키지 않은 파일을 고치는 등 실수를 막은 프롬프트
- 앱 안에서 쓰는 AI 프롬프트(시스템 프롬프트 등)를 새로 만들거나 고친 경우

**기록하지 않는 것**
- "안녕", "응", "맞아", "고마워", "ㅇㅋ", "다시 해 줘", "계속" 같은 짧은 말
- 오타 수정, 파일 위치 묻기처럼 결과가 남지 않는 단순 요청
- 이미 기록한 것과 거의 같은 프롬프트

**쓰는 방법**
- 프롬프트는 담당자가 쓴 **원문 그대로** 넣습니다. 다듬거나 요약하지 않습니다.
- API 키, 비밀번호, Supabase 주소, 개인정보는 `***`로 가립니다.
- 새 기록은 `## 기록` 맨 아래에 번호를 이어서(P-01, P-02 …) 추가합니다. 이전 기록은 고치거나 지우지 않습니다.
- 기록을 추가했다면 `## 요약`의 표도 한 줄 갱신합니다.
- 앱 안 AI 프롬프트를 고쳤다면 `## 앱 안 AI 프롬프트 버전`에도 한 줄 추가합니다.
- 기록했다면 작업 끝에 "프롬프트 기록에 P-00을 추가했습니다"라고 알려 줍니다.

**기록 형식** (이 형식만 사용)

````

- 문제 유형: 환각(없는 정보 지어냄) / 다른 파일 수정 / 기존 코드 삭제 / 형식 깨짐 / API 버전 오류 / 없음 등
````

## 요약

보고서의 "전략 개요"와 "문제 해결 표"가 되는 부분입니다. 기록이 쌓일 때마다 갱신합니다.

**프롬프트 전략 개요**: 참고 이미지를 함께 주고, 화면 영역별로 무엇을 넣을지 나눠서 요청했다. 결과가 모호했던 부분(보고서 형식, 예산 단위)은 분량·단위·입력 방식을 숫자와 구체어로 다시 지정해 해결했다. 실제 데이터(Open-Meteo)와 나중에 넣을 데이터(경쟁사 DB)를 처음부터 구분해 알려 줘서 샘플을 바꿔 끼우기 쉬운 구조로 만들었다.

| 문제 유형 | AI가 한 실수 | 해결한 프롬프트 전략 | 기록 |
|---|---|---|---|
| 없음 | - | 화면 영역별 요구 + 참고 이미지별 참고 범위 + 실데이터/샘플 구분을 한 번에 지정 | P-01 |
| 형식 깨짐 | 보고서를 긴 문장 나열 + 여러 장으로 만들고, 예산을 배수로만 표시 | 분량(1장)·단위(€ 금액)·입력 방식(최소·최대 직접 입력)을 구체적으로 지정 | P-02 |

| 없음 | - | 적용 범위의 예외(날씨 카드 제외)와 배치 이유(넓은 칸에 예산)를 함께 지정 | P-04 |
| 없음 | - | 색은 화면에 이미 있는 요소를 기준으로 지정("쿨링패드 요소의 보라색") | P-05 |
| 없음 | - | 다른 카드 요소를 기준으로 통일 요청, 넣을·뺄 문구는 원문 그대로 지정 | P-06 |

**처음 시도와 문제**
- 처음 프롬프트: P-01 (보고서 형식만 "보고서 형식으로"라고 요청)
- AI가 한 실수: 근거를 긴 문장 목록으로 나열한 2~3장짜리 PDF를 만들어 읽기 어렵고 AI가 쓴 티가 났음. 예산도 "1.6x" 같은 배수로만 보여 줘서 실제로 얼마를 써야 하는지 알 수 없었음.

**해결 전략**: "1장", "읽기 쉽게", "배수 말고 구체적인 비용", "최소·최대를 사용자가 직접 입력"처럼 결과물의 분량·단위·조작 방법을 숫자와 구체어로 못박음. 그 결과 PDF는 핵심 수치 4칸 + 번호 권고 + 표 중심의 1장 권고서로, 예산은 주간 총액을 € 단위로 나누는 방식으로 바뀜.
**결과**: `weather_data.py`(€ 배분 규칙, 합계가 정확히 맞는 반올림), `weather_page.py`(3단 레이아웃, 예산 입력·슬라이더, € 그래프), `weather_report.py`(A4 1장 권고서), `weather_style.css`(이 탭만 전체 폭, 칸 높이 맞춤, 둥근 막대), `weather.md`
**다음에 쓸 팁**: "보고서 형식으로"처럼 모호하게 말하면 AI는 문장을 길게 늘어놓는다. 분량(1장)과 읽는 사람 기준(직관적으로, 표·숫자 위주)을 같이 적어야 한다.

**해결 전략**: "날씨 정보를 제외한"처럼 적용 범위의 예외를 함께 적고, 박스 내용을 서로 바꾸는 이유("더 넓은 박스에 예산이 들어가게")를 같이 말해 AI가 의도대로 배치하게 함. 비율 설정은 "추천 비율 사용" 토글로 추천값과 직접 설정을 오갈 수 있게 만듦.
**결과**: `weather_data.py`(채널 비중 직접 설정 지원, 추천 비중 함수), `weather_page.py`(넓은 칸에 주간 예산 + 채널 비율, 좁은 칸에 채널 액션, SUIT 글꼴 불러오기), `weather_report.py`(직접 설정한 비율을 보고서에 표시), `weather_style.css`(흰 카드 배경, 입력칸, 글꼴), `weather.md`
**다음에 쓸 팁**: "팀 공용 폰트"처럼 이름 없이 말하면 AI가 어떤 글꼴인지 찾아봐야 한다. 글꼴 이름이나 파일 위치(예: common/fonts의 SUIT)를 같이 적으면 더 빠르다.

### P-05 · 2026-10-24 · 간격·비율 다듬기, 예산 카드 가독성 개선

- 분류: 디자인
- 문제 유형: 없음

**잘 쓴 프롬프트 (원문)**
```text
-상단 날씨권역에서 북부 서부 동부 남부 글씨를 좀만 기워줘.
-크게 왼쪽 탭과 오른쪽탭(경쟁사 재고시그널, 오늘의추천) 간격을 좀만 줄여줘.
비율에 맞게

```

- 문제 유형: 없음
