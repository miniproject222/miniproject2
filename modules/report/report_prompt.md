## AI에게: 기록 규칙

이 파일을 읽은 AI는 `modules/report/` 작업이 끝날 때마다 아래 규칙대로 기록해 주세요.

**기록하는 것**
- 결과가 잘 나와서 담당자가 받아들인 프롬프트
- 처음엔 실패했지만 프롬프트를 고쳐서 해결한 경우 (실패한 프롬프트와 고친 프롬프트 모두)
- AI가 틀린 정보를 지어내거나(환각), 시키지 않은 파일을 고치는 등 실수를 막은 프롬프트
- 앱 안에서 쓰는 AI 프롬프트(시스템 프롬프트 등)를 새로 만들거나 고친 경우

**기록하지 않는 것**
- "안녕", "응", "맞아", "고마워", "ㅇㅋ", "다시 해 줘", "계속" 같은 짧은 말
- 오타 수정, 파일 위치 묻기처럼 결과가 남지 않는 단순 요청
- 이미 기록한 것과 거의 같은 프롬프트

**쓰는 방법**
- 프롬프트는 담당자가 쓴 **원문 그대로** 넣습니다. 다듬거나 요약하지 않습니다.
- API 키, 비밀번호, Supabase 주소, 개인정보는 `***`로 가립니다.
- 새 기록은 `## 기록` 맨 아래에 번호를 이어서(P-01, P-02 …) 추가합니다. 이전 기록은 고치거나 지우지 않습니다.
- 기록을 추가했다면 `## 요약`의 표도 한 줄 갱신합니다.
- 앱 안 AI 프롬프트를 고쳤다면 `## 앱 안 AI 프롬프트 버전`에도 한 줄 추가합니다.
- 기록했다면 작업 끝에 "프롬프트 기록에 P-00을 추가했습니다"라고 알려 줍니다.

**기록 형식** (이 형식만 사용)

````
### P-00 · YYYY-MM-DD · 작업 제목

- 분류: 기능 구현 / 버그 수정 / 디자인 / 데이터 / 앱 안 AI 프롬프트 / 기타 중 하나
- 문제 유형: 환각(없는 정보 지어냄) / 다른 파일 수정 / 기존 코드 삭제 / 형식 깨짐 / API 버전 오류 / 없음 등

**잘 쓴 프롬프트 (원문)**
```text
담당자가 쓴 프롬프트 그대로
```

**처음 시도와 문제** (처음부터 잘 됐으면 "없음")
- 처음 프롬프트: "..."
- AI가 한 실수: ...

**해결 전략**: 프롬프트에서 무엇을 바꿨더니 해결됐는지 한두 줄
**결과**: 무엇이 만들어졌는지, 바뀐 파일
**다음에 쓸 팁**: 다른 작업에도 쓸 수 있는 요령 한 줄
````

### P-03 · 2026-10-23 · PDF 다운로드, KPI 카드 축소, 매출 추이 위치 변경

- 분류: 기능 구현
- 문제 유형: 형식 깨짐 (PDF 한글 폰트)

**잘 쓴 프롬프트 (원문)**
```text
1. 리포트 다운로드는 md파일이 아닌 PDF파일로 다운로드 받을 수 있게
2. 사진 화면 이 높이 1/3사이즈로 변경해줘 이 내용 보단 하단의 내용이 더 중요해서 화면에 바로 볼 수 있도록
3. 최근 14일 매출 추이가 바로 아래에 있는 내부요인, 외부요인 하단으로 위치 변경해줘
```

**처음 시도와 문제**
- 처음 시도: reportlab으로 공통 폰트(SUIT .otf)를 등록하려 했으나 "postscript outlines are not supported" 오류. fpdf2로 바꾼 뒤에는 SUIT에 '•' 글자가 없어 글머리표가 빠짐
- AI가 한 실수: 처음 PDF에서 표 칸 전체가 보라색으로 칠해지고 테두리가 검정으로 나옴

**해결 전략**: 바꿀 내용을 번호로 나누고 이유("하단 내용이 더 중요해서 바로 보이도록")를 함께 적어, AI가 KPI 카드를 단순히 줄이는 대신 한 줄형 카드로 다시 만들도록 유도함. PDF는 실제로 만들어 열어 보고 표 색, 테두리, 글머리표를 고침
**결과**: report_download.py(fpdf2 + SUIT 폰트 PDF), report_page.py(한 줄 KPI 카드, 매출 추이를 내부/외부 요인 아래로), report_style.css(report-kpi), report.md 갱신. requirements.txt에 `fpdf2>=2.8` 한 줄 추가 필요(담당자가 직접)
**다음에 쓸 팁**: 한글 PDF는 폰트 형식(.ttf/.otf)에 따라 라이브러리 지원이 다르므로, 만든 PDF를 직접 열어 확인하라고 요청한다

### P-04 · 2026-10-24 · PDF 리포트 양식 3가지 (기업 보고서 양식)

- 분류: 기능 구현
- 문제 유형: 형식 깨짐 (PDF 표 색, 글자 줄바꿈)

**잘 쓴 프롬프트 (원문)**
```text
1. 내가 작성하고 있는 페이지는 서리로 유지를 하고 다른페이지는 PM이 변경할거야
2. pdf로 다운로드 받았을때 보닌까 양식이 클로드에 있는 양식인거 같아 > 클로드 보고서 양식 말고 화면에 출력되는 내용 그대로 보고서 페이지로 옮기지만 양식은 대기업에서 많이 사용하는 양식 3가지로 설정해줘 > 내가 확인하고 팀원들과 상의해서 어느 양식으로 사용할지 정해줄게
```

**처음 시도와 문제**
- 처음 프롬프트: P-03의 "리포트 다운로드는 md파일이 아닌 PDF파일로 다운로드 받을 수 있게"
- AI가 한 실수: 양식을 지정하지 않자 마크다운 문서를 옮긴 듯한 단순한 PDF를 만듦. 3가지 양식 첫 결과에서는 경쟁사 표 칸이 진한 색으로 칠해져 글자가 안 보이고, 원페이지형 KPI 숫자가 두 줄로 잘림

**해결 전략**: "내용은 화면 그대로, 양식만 다르게"로 내용과 형식을 나눠 지시하고, 바로 하나로 정하지 않고 3가지를 만들어 팀이 고르게 함. 만든 PDF를 직접 열어 보고 표 색과 줄바꿈을 고침
**결과**: report_pdf.py(① 기안 보고서형, ② 경영진 보고형, ③ 원페이지 대시보드형, 퍼널과 매출 차트를 PDF 안에 직접 그림), report_download.py(양식 선택 + 다운로드), report.md 갱신
**다음에 쓸 팁**: 문서 양식을 바꿀 때는 "내용은 그대로, 양식만"처럼 바꿀 것과 유지할 것을 나눠 말하고, 후보 여러 개를 받아 비교한다

### P-05 · 2026-10-24 · UTM·GA4 연결 준비 (샘플 → GA4 자동 전환)

- 분류: 데이터
- 문제 유형: 런타임 오류 (0으로 나누기)

**잘 쓴 프롬프트 (원문)**
```text
1. UTM 붙이기, GA4가 자동 분류 모두 사용 예정이고 페이지는 배포 후 링크를 줄게 설정해줘
2. PM님이 내가 DB를 직업 올리라고해서 직접 올릴거고 나중에 커밋 푸시할 때 잘 적어줘
```

**처음 시도와 문제**
- 처음 프롬프트: 위와 같음
- AI가 한 실수: 퍼널 전환율 계산이 지난 기간 값으로 나누는 구조라, GA4를 막 연결해 지난 기간 데이터가 0이면 앱이 멈출 수 있었음

**해결 전략**: 아직 없는 정보(쇼핑몰 주소, GA4 키)는 비워 두고 "있으면 GA4, 없으면 샘플"로 자동 전환하게 요청. 연결 전이라 GA4 응답은 가짜 데이터로 시험했고, 지난 기간이 0인 경우를 넣어 보다가 오류를 찾아 고침
**결과**: report_ga4.py(GA4 Data API 조회, UTM 링크 만들기), report_data.py(GA4 자동 전환, 유입 채널 계산), report_page.py(유입 채널 카드, 0 나누기 방지), report_pdf.py(3가지 양식에 유입 채널 추가), 샘플 JSON에 utm 추가(합계가 화면 숫자와 일치)
**다음에 쓸 팁**: 외부 연결을 미리 만들 때는 "연결 정보가 없으면 샘플로"를 조건으로 주고, 처음 연결했을 때처럼 데이터가 비어 있는 경우도 시험하게 한다

### P-06 · 2026-10-24 · Keepa 경쟁사 비교, 공통 DB 연결, 해결안 A/B 테스트

위 작업이 완료되면 아래 내용 확인 후 작업 시작(자사몰 링크 https://seori-site.vercel.app/)
