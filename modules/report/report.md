# 1. 분석 리포트 (`report`)

amazon.de 검색어별로 '보이는 만큼 눌리는지'(클릭 점유율 ÷ 노출 점유율) 찾고 원인 분석 (기준 문서: 루트 `문제 시나리오.md`), 경쟁 포지션 분석 (내부/외부 요인, 경쟁사 비교), 문제 도출, 리포트 다운로드(PDF)

**검색어 클릭 분석만 더미를 씁니다** (검색어 성과 리포트는 판매자 계정에서만 나오기 때문). 모양·크기·사건은 실제 데이터(DWD 기온, Keepa)에서 가져오고 우리 계정 안의 숫자만 더미로 채우며, 화면에 항목마다 `가상 / 실제 / 가정`을 표시합니다. 경쟁 포지션 분석은 지금처럼 실제 데이터만 씁니다.

## Keepa 사용 규칙 (토큰 한도 600)

- 화면을 열 때는 Keepa를 호출하지 않고 스냅샷만 보여 줍니다.
- 조회: 경쟁사 비교 > 'Keepa 최신값 조회'에서 확인 PIN 입력 + 동의 후 1회 (약 10토큰). `KEEPA_FETCH_PIN`이 없으면 조회 불가.
- 사용량은 `data/report_keepa_usage.json`에 기록하고, 남은 한도가 예상 사용량보다 적으면 막습니다.
- 로컬에서 조회한 뒤 스냅샷·사용량 파일을 커밋하면 배포 앱은 토큰 없이 마지막 값을 보여 줍니다.
- secrets의 report 칸: `KEEPA_API_KEY`, `KEEPA_FETCH_PIN`

## GA4 연결

- secrets의 report 칸: `REPORT_GA4_PROPERTY_ID`, `REPORT_GA4_CREDENTIALS` (requirements: `google-analytics-data`)
- 유입 채널: `sessionSource / sessionMedium / sessionCampaignName` × `sessions, ecommercePurchases, purchaseRevenue`
- 퍼널: 방문 = `sessions`, 이후 `view_item` → `add_to_cart` → `begin_checkout` → `purchase` (eventCount)
- 기간: 최근 30일 vs 그 전 30일, 1시간 캐시

## 경쟁사 표시 규칙 (2026-10-24)

- 대시보드에는 **냉감패드 판매 순위 상위 2개사 + 서리(가정 3위)**만 표시합니다. (`report_competitor.py`의 `REPORT_TOP_RIVALS = 2`)
- 순위 기준: 경쟁사 DB '구분'의 "독일 N위 (Keepa 판매순위)". Keepa Amazon.de 판매 순위(2026-10-24 조회)로 침구류 냉감패드만 비교했습니다 (토퍼·전동·젤·일반 방수커버 제외).
  - **2026-10-24 재조사 결과**: 1위 Traumnacht 패드(판매 순위 6,992), 2위 Mara Vital(245,133), 3위 Herlag(299,729), 4위 RIBECO(323,890), 5위 Novilla(412,593)
  - 대시보드: 경쟁사 Traumnacht·Mara Vital + **서리 = 3위 Herlag 가정** (`REPORT_SEORI_PROXY = "Herlag"`). 서리의 판매 실적(판매 순위·가격·평점·리뷰·㎡당 가격)은 Herlag(B0F2FN34BS) Keepa 값, 제품·원사·Q-max·인증·시험은 서리 기획 + 완제품 가정. 화면에 '독일 3위 (가정: Herlag 실적)'으로 표시
  - 주의: Herlag 판매 페이지에는 냉감 기능 표기가 없음(여름·겨울 양면 사계절 커버). 엄밀한 냉감패드 3위는 RIBECO일 수 있음 (상수 하나로 변경 가능)

## 해결안 A/B 아침 분석 (③ 광고 소재 탭 → ① 리포트)

- ③ 탭이 실행 결과를 `store_set("media", {...})`로 저장하면, ① 탭이 **매일 아침(한국 08:00 이후 첫 접속)** 한 번 분석해 `ab_daily`에 저장하고 그날 하루 같은 값을 보여 줍니다. 전날 분석과 비교한 변화와 지난 14일 기록도 보여 줍니다.
- 아침에 결과가 없었다가 그날 ③ 탭이 저장하면 그때 한 번 분석합니다.
- Streamlit에는 예약 실행이 없어서 '그날 첫 접속'에 분석합니다. 접속이 없어도 정해진 시각에 돌리려면 GitHub Actions 등 예약 실행이 필요합니다 (PM 결정).
- **③ 탭 담당자에게 요청할 저장 형식** (`media_ab_result_dummy_202610.json`과 같은 모양):

```python
store_set("media", {
    "ab_result": {"source": "실제", "period": "...", "query": "kühlende matratzenauflage", "market_ctr": 0.03,
                  "variants": [{"name": "A", "desc": "...", "impressions": 0, "clicks": 0, "sessions": 0, "units": 0},
                               {"name": "B", "desc": "...", "impressions": 0, "clicks": 0, "sessions": 0, "units": 0}],
                  "cac": {"before": {"label": "...", "spend": 0, "new_to_brand_orders": 0, "sales": 0}, "after": {...}}},
    "utm": [{"source": "google", "medium": "cpc", "campaign": "...", "sessions": 0, "orders": 0, "revenue": 0}],
    "updated_at": "2026-10-25 07:30",
})
```

- 판정: 클릭률이 유의하게(p<0.05) 높고 구매 전환율이 0.5%p 넘게 떨어지지 않으면 B 승리 (③ 탭 판정 규칙과 같음). 아직 유의하지 않으면 안별로 더 필요한 노출 수를 계산합니다.
